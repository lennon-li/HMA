## 2. Authority model (A1, A3)

Rule: every authority the host uses traces to one challenge-bound human approval in the core chain.
The host may not self-issue authority. No new approval channel is created.

### 2.1 Two additive approval fields (requires architecture §6 amendment — D1)

Following the 2026-09-08 worktree-digest precedent, `ApprovalBinding` gains two optional fields. Each
is omitted when empty, so existing approvals and digests are unchanged.

- `acceptance_contract_digest` — required on the `ACCEPTANCE_CRITERIA -> PLANNING` approval for any run
  that uses an outcome contract; carried unchanged by every later approval of that run.
- `execution_lease_digest` — permitted only on the `IMPLEMENTATION_AUTHORIZATION -> IMPLEMENTATION`
  approval for one unit.

A change to either bound document invalidates the approval (existing §6 rule: "a change to any actually
bound field invalidates the approval").

### 2.2 Acceptance contract (A3) — `hma.acceptance-contract/v1`, canonical JSON

One immutable document per approved criteria set: `run_id`; intent/scope text; non-goals; criteria list
`{id, statement, check: {executable, argv, working_dir}, threshold, evidence_requirement}`; risk;
deliverables; budgets ceiling. The core `criterion` record set for the run must have exactly the contract's
criterion IDs. Changing a statement, check, or threshold changes the digest. The digest then no longer
matches the approval, so verification is refused until a human approves a rewind to
`ACCEPTANCE_CRITERIA` and a new contract. Result dispositions (PASS/FAIL) stay in core `criterion`
records; the contract never holds results.

Precedence: risk, routes, permissions, budgets are defined once. The contract holds the ceilings; the
lease holds the per-unit grant and must be within the contract; the core route approval holds route
identity. A conflict fails closed.

### 2.3 Execution lease (A1) — host record `lease`, `hma.host.lease/v1`

Fields: `run_id`, `unit_id`, `acceptance_contract_digest`, `route_approval_digest`, permitted
routes/permission classes, `max_attempts`, wall-time and declared-cost ceilings, `forbidden_actions`,
`issued_at`, `expires_at`. The lease digest must equal `execution_lease_digest` in the latest applicable
core approval for that unit (lookup reuses the existing route-approval binding logic in
`cmd/hma/transition.go`). A lease is active only while all hold:

1. the core run is not terminal (closes H4 class);
2. the unit's projected core stage is `IMPLEMENTATION` or `IMPLEMENTATION_REVIEW` and no later approved
   rewind exists for the unit, the whole run, or a unit it depends on;
3. now < `expires_at`; attempts and costs remain;
4. contract and route digests match current core state.

Within an active lease the host may record decision/preflight/dispatch/review for repair attempts
without a new human approval. A lease never records a core transition. Rework that needs a stage rewind
(e.g., a finding against the plan) voids the lease; the next action is `ESCALATE_TO_HUMAN`.

Dependent units (audit "open product-contract" item): Gate B persists an optional `invalidated_units`
list on plan-unit rewind transitions; condition 2 checks it. Pre-existing records without it remain valid
and are treated as invalidating only the named unit (current behavior).

## 3. Verify-loop and audit-skill integration (A2, A4)

### 3.1 Verify-loop (A2)

Observed contract (repaired controller, uncommitted in Obsidian at the time of writing): own durable
journal, attempt counting, recovery, private-clone execution, `bounded-checks-only` result, dispatch
through `agent-dispatch`.

Design: the controller stays the execution journal. HMA owns authority. One bridge per attempt:

- Verify-loop gains an optional envelope field `authority_hook: {argv}`. The controller runs it before
  each worker launch, including after resume and before any escalation route. Non-zero exit stops the
  loop with `authority-refused`. The hook is `hma host attempt --store S --run_id R --unit U --lease L
  --route <json>`; it checks the lease (§2.3), checks attempt/cost ceilings, requires a fresh exact-route
  preflight record, and appends one host `dispatch` record. So every actual attempt is one HMA-bound
  dispatch; the host count cannot miss inner attempts.
- Evidence: HMA does not trust the loop's green. After transfer back to the live checkout, HMA reruns
  each contract check through its own no-shell evidence capture, bound to head/diff/worktree. The loop
  journal digest is stored as supporting implementer evidence only.
- The envelope's attempts/time/cost must each be ≤ the lease's remaining amount (A6). Escalation routes
  must be in the lease's permitted route set.

This requires a small Verify-loop change (Obsidian repository) — a cross-project write that needs
Lennon's explicit approval (D5).

### 3.2 Independent-audit skill (A4)

- Import unit: one audit report = one host `review` record binding report digest, packet digest
  (`prepare_packet.py` manifest), reviewer route, isolation level, and target head/diff/worktree.
  Isolation `partial` or `compromised`, same exact model as implementer (normal risk), or same
  provider/model family (high/critical, final) is refused for acceptance.
- Findings: the import writes **one cumulative core findings snapshot** containing all prior unresolved
  findings plus new ones (the projection replaces the whole snapshot, so per-finding records would hide
  earlier ones). Disposition rule, deterministic and versioned: a finding linked to a contract criterion,
  a kernel invariant, or with severity critical/high → `BLOCK`; medium/low without such link →
  `BLOCK` until a human assigns `WAIVABLE`/`ADVISORY` through the existing waiver/override path. Severity
  never downgrades a blocker. A finding leaves the snapshot only when an independent review bound to
  newer bound inputs marks it resolved; fresh evidence at the same head is enough for evidence-only gaps.
- Reopen: a resolved finding ID that reappears is counted as reopened in the scorecard.

## 4. Checkpoint policy (A5) and budgets (A6)

### 4.1 Checkpoint inputs and triggers

Input: changed paths and path classes; metadata-only changes (mode, rename); contract, policy, permission,
route, or criteria digest deltas; interface/schema/protocol deltas; risk; unit completion;
external-effect events (publish, push, deploy, network write) even with no diff; final-closure request.

Kernel triggers (compiled, cannot be removed by configuration): any contract/criteria/permission/policy
delta; risk ≥ high; schema/protocol/public interface change; security/approval/routing/evidence/closure
code; any external-effect event; unit completion; final closure. Per-change independent review remains
mandatory for every coding change regardless.

Audit packet binds: run, unit, head, diff, worktree digest, contract digest, policy digest, evidence
digests, open-findings snapshot digest, reviewer route. A change in any of them makes the packet stale.

Reviewer independence: normal risk — different exact model from the implementer; high/critical and final
— different provider and model family (§13). Same-route substitution is refused.

### 4.2 Budgets

- Envelope or nested request ≤ remaining lease for every ceiling; e.g. lease attempts 5 → accept 4 or 5,
  refuse 6 (corrects v1, which stated the comparison backwards).
- Attempts counted: every implementation dispatch, including nested Verify-loop attempts, reroutes, and
  direct work. Review launches are not implementation attempts.
- Crash before launch: reservation released only if the dispatch receipt proves no launch. After launch:
  the attempt counts.
- Same material failure twice → stop and classify (§17); no third blind attempt.
- Unmetered paid or token-ceiling routes fail closed (same rule as Verify-loop).
