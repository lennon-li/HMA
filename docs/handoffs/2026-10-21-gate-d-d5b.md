# Gate D part D5b - findings disposition (2026-10-21)

Scope: Gate A v3 §4.1 and architecture §9. Severity never sets disposition. BLOCK needs a kernel-rule violation
HMA reproduces; WAIVABLE needs a plan budget HMA measures as exceeded; everything else is ADVISORY. D5c (full
review packet) and D6 (architecture amendment) are not part of this unit.

## What changed

- `internal/host/findings_import.go`: `MapAuditFindings(raw, facts)`. A finding's `hma_ref` (the report
  contract's existing field, `{kind, id}`) is a claim HMA checks, never believes:
  - `kernel_rule` + a registered id (`KernelRules`: `no_shell`) whose predicate holds now -> BLOCK.
  - `declared_budget` + a measured budget (`MeasuredBudgets`: `max_files`, `max_diff_lines`) that HMA measured as
    exceeded -> WAIVABLE.
  - Anything else (unknown id, wrong kind, claim without fact, severity, criterion link) -> ADVISORY/PARK.
  - Ids starting `HMA-` are reserved: a report that uses one is refused (`HOST_FINDINGS_IMPORT_INVALID`).
  - `AddEstablishedFindings` raises, on every import and whatever the report says, `HMA-BUDGET-<name>`
    (WAIVABLE) for each exceeded budget and `HMA-KERNEL-<rule>` (BLOCK) for each registered rule that holds. An
    approving review that omits them cannot clear them; the next import re-raises while the fact holds.
- `cmd/hma/disposition.go`: `findingFacts` computes the facts from HMA's own state and measurement (no auditor
  text, no auditor command), `requireFindingsResolved` is the gate check.
  - `no_shell`: a verification command of the unit's current-generation plan reaches a shell under
    `evidence.RejectShell` (the capture's own policy). A tool merely missing from PATH is not a shell violation.
  - Budgets: `git diff --numstat --text` with attributes neutralised (`core.attributesFile=/dev/null`,
    `--attr-source=<empty tree>`, large `bigFileThreshold`) of the committed change from the approved base to HEAD;
    for a dirty-approved target the base-to-worktree tracked change plus untracked non-ignored files. A rename
    counts as a deletion and an addition; a merge as the base-to-target tree difference.
- `cmd/hma/transition.go`: the review-to-verification gate and the verified-outcome closure refuse while any
  BLOCK finding stands, or a WAIVABLE finding has no active human waiver (`HOST_FINDINGS_UNRESOLVED`). The gate
  checks the unit's findings plus unowned ones; closure checks all.
- `cmd/hma/review.go`: findings import computes the facts under the locks after the live-target and repository
  checks. Review import still escalates a `pass` that carries an `hma_ref`.

## Audit r1 (Ming, Claude Opus 5.5 high) FAIL: F1-F3 high, F4-F6 medium, F7-F8 low; all addressed

- F1 report id squatting the measured id: reserved `HMA-` prefix; the established findings are always appended.
- F2 an approving review cleared a held BLOCK: HMA re-raises `HMA-KERNEL-<rule>` on every import.
- F3 no gate read dispositions: the gate and closure checks above.
- F4 `evidence_current` registered but not a kernel fact: removed. A stale credit is already void at the gate.
- F5 `no_shell` fired for a missing tool: now `evidence.RejectShell`.
- F6 `.gitattributes` hid lines: attributes neutralised, files read as text.
- F7 dirty content not measured: measured for a dirty-approved target.
- F8 stale comment fixed; `authority` removed from the registry (its BLOCK is the unowned
  `UNAUTHORIZED_DISPATCH` finding, which already stops the gate and which no review import clears).

## Audit r2 (Ming, Claude Opus 5.5 high) FAIL: N1 high; N2 to N4 medium; N5 to N9 low

- N1 a waiver survived a change of the measured artifact: the HMA budget finding id now carries a 16-character
  tag of the reviewed artifact (`HMA-BUDGET-<name>-<tag>`). A new artifact is a new finding that an old waiver
  (scoped to the old id) does not cover; the same artifact keeps the same id.
- N2 a waiver recorded after a review stales that review at the gate (`requireOnlyOwnSnapshotsSince` allows
  only snapshot records): kept, and documented. The path is a waiver, then a fresh independent review of the same
  artifact; it re-raises the same finding id, which the waiver already covers. `TestWaivableNeedsHumanWaiver`
  walks it to a passing gate. Widening the stale-binding allowlist was not done (Gate C binding stays strict).
- N3 the dirty measurement followed untracked symlinks and could block on a FIFO: `untrackedLines` uses Lstat,
  counts a symlink as one line (git's own count), opens no FIFO or device, and reads a regular file with a
  16 MiB cap.
- N4 a human override could turn an HMA-measured WAIVABLE into ADVISORY: `engine.EvaluateResolution` refuses an
  override of any finding whose id source part starts `HMA-` (`CANNOT_OVERRIDE_HMA_ESTABLISHED_FINDING`);
  report-sourced findings are unchanged. Established findings are resolved by a waiver only.
- N5 `no_shell` resolved the executable differently from the capture: it uses the capture's own resolver
  (`evidence.ResolveExecutable`).
- N7 closure allowed `VERIFIED_SUCCESS` while a waiver was active: the closure branch refuses it
  (`HOST_FINDINGS_UNRESOLVED`); `VERIFIED_WITH_WAIVERS` is unaffected.
- Not done, recorded: N6 (the live `.git/config` can over-count, and run a clean filter, in the dirty
  measurement; the stated limit "can only under-count" was wrong), N8 (a native, legacy-manual review never
  computes HMA facts, so the D5b guarantees depend on the packet-import review mode), N9 (measurement
  definitions under- and over-count by design: renames, merges, binary lines). The structural answer to N6 is the
  single verified object store recommended in the D5a follow-up.
- Tests: `TestBudgetWaiverDoesNotSurviveNewArtifact`, `TestUntrackedLinesBounded`,
  `TestOverrideRefusedForEstablishedFinding`, `TestWaivableNeedsHumanWaiver` (extended). Mutants caught: artifact
  not in the id, symlink and FIFO followed, override allowed.

## Deviations from the approved design (D5B-DESIGN)

- Reference format: the report contract's `hma_ref {kind, id}`, not new flat `kernel_rule` / `budget` fields.
- Registry: only `no_shell`. `identity`, `separation`, `transition_integrity` and evidence currency are enforced
  by refusing the import itself, so they never reach a finding; unauthorized dispatch is already an unowned BLOCK.
- Criterion link: nothing implemented. A failed check leaves the criterion uncredited (D5a); a link on a
  finding cannot raise a disposition under §4.1.
- Scope added by Lennon's decision: the finding-resolution gate (F3), which the first draft left to Gate E.

## Limits

- The closure-side call is not exercised end to end: the core still refuses successful verified outcomes
  (`OUTCOME_NOT_IMPLEMENTED`). `requireFindingsResolved` is unit tested with the closure form (all units).
- Measurement reads under the live `.git/config` (the class D5a rounds found); it can over-count and, for a
  dirty target, run a configured clean filter (N6, open).
- A merge, rename and submodule pointer are counted as stated above; none has a dedicated test.

## Tests (exit: `TestDispositionFollowsSection9`)
