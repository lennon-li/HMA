## Revocation (`engine.RevokedAt`, pure)

A reservation's effective `valid_until` is the minimum of its recorded lease end and the time of every
applicable revocation after its generation's issuing approval: any approved return to Grounding or Acceptance
criteria (any unit tag); any later approved transition of the unit or the whole run out of Implementation
authorization; a plan dependency's return to an earlier gate or its Independent validation correction; a
terminal outcome. Event time is the earlier of approval and record time; an unreadable time revokes from the
issuer. Computed from the whole chain, so ingestion order does not matter and it only decreases. A new
generation never revives an old reservation (the old one is revoked by the unit leaving Implementation
authorization).

## Reconciliation (`host.Reconcile`, pure; `hma host reconcile`)

Declared namespaces: the ledger namespace of every loop admission. Every run directory there
(`runs/<id>/receipt.json`) that started at or after the run's first core record must match exactly one
reservation or HMA-generated review dispatch, by receipt `run_id` equal to its directory name; reservations
must be in their admission's namespace and not review mode, review dispatches in review mode; and the launch
time must be in `[valid_from, valid_until)` (reservations: effective `valid_until`; reviews: packet TTL, cut by
a terminal outcome). A record counts as used only by an authorized launch. Unreadable or missing receipts,
no match, ambiguous match (a reservation and a review sharing an id), reuse, namespace or mode mismatch, and
launches outside validity are `UNAUTHORIZED_DISPATCH`. Loop evidence must match its admission (envelope,
namespace, unit) and have a reservation for every journal attempt. Unlaunched reservations are listed and stay
charged.

`hma host reconcile --input` (envelope plus `policy_path`) runs
under the host and core locks, appends a `launch_reconciliation` host record, and, when anything is
unauthorized, one core finding record carrying the current findings plus one unowned BLOCK per entry
(`UNAUTHORIZED_DISPATCH:<id>:<reason>`). Unowned findings survive every review snapshot.

## Gate

`IMPLEMENTATION_AUTHORIZATION -> IMPLEMENTATION_REVIEW` and `IMPLEMENTATION_REVIEW -> VERIFICATION` are refused
while an unauthorized-dispatch BLOCK is in the core findings (`HOST_UNAUTHORIZED_DISPATCH`), and, for a unit
with reservations, until a clean reconciliation newer than its last reservation is bound to the current core
head (`HOST_RECONCILIATION_REQUIRED`).

## D4 r1 remediation (Liz)

- **F01** The gate is bound to the ledger: the latest reconciliation must be clean, have no launch authority
  or journal recorded after it, bind the current core head, and its inventory digest (namespace, run directory,
  receipt SHA-256, error) must equal a fresh scan, taken under the host lock. It applies to every run that
  declares a ledger namespace, including review-only runs.
- **F02** Each reservation is checked with its own generation's plan: `hma host attempt` stores the plan
  (`<store>/artifacts/plan-<digest>.json`, verified on read) and reconciliation resolves the generation's issuing
  approval's `accepted_plan_digest`; a missing plan is `GENERATION_PLAN_MISSING`. `hma host reconcile` no longer
  takes a plan.
- **F03** Review dispatch validity is cut by `engine.RevokedReviewAt`: the unit's return to an earlier gate, a
  dependency rewind or correction (per the plan at issue; every other unit when unknown), a whole-run return to
  Grounding or Acceptance criteria, and a terminal outcome; the unit's own forward moves do not revoke it.
- **F04** Review packets bind the ledger (`ledger_dir`, absolute, required); review import reads the receipt
  only from it; reconciliation scans every admission and review namespace and checks review launches against
  their packet's namespace.
- **F05** No widening: `valid_from` is the next whole second, which `hma host attempt` waits for before
  granting; reconciliation compares exactly.
- **F06** A journal with attempts must match exactly one admission; its attempts are checked even without one.
- **F07** Loop evidence records the journal's live root and clone baseline digest; both must equal the
  admission's.
- **F08** `hma host attempt` records a dated `policy_revocation` when it sees a current policy other than the
  plan's; reconciliation cuts validity there, needs the current policy (`policy_path`) when reservations exist,
  and marks a changed but undated policy `POLICY_REVOCATION_UNPROVEN`.
- **F09** `next_action` is `ESCALATE_TO_HUMAN` while any unauthorized-dispatch BLOCK stands.

## Audit r2 fixes (Liz D4 r2 FAIL, three high findings)

- **R2-F01** A review dispatch belongs to the unit's lease generation current at its core head (the
  latest `engine.IssuesLease` approval). Its end is the minimum of the packet TTL, a terminal outcome, the
  generation's wall-time end (approval time plus the unit's `max_wall_minutes` in the generation's own
  plan), every core revocation (`RevokedReviewAt`, which now also counts the unit's return to
  Implementation authorization, a correction generation), and every applicable policy revocation. No
  generation is `GENERATION_MISSING`; no stored plan is `GENERATION_PLAN_MISSING`; no presented policy is
  `POLICY_NOT_PRESENTED`. The nil-plan fallback is removed: a review without its plan is refused.
- **R2-F02** `host.PolicyRevokedAt` returns the earliest recorded `policy_revocation` of a plan policy that
  applies to a generation: one recorded at a core head at or after the generation's issuer. Replay and
  fresh issuance in `hma host attempt` and reconciliation all use it, so restoring the policy bytes
  revives nothing; a later approved generation is not revoked by an earlier record. A revocation whose
  core head is unknown applies to every generation.
- **R2-F03** The ledger scan keeps the receipt's launch identity (`agent`, `model`, `provider`, `effort`,
  `packet_sha256`, `project_root`, `launch_head`, `launch_worktree_sha256`). Review launches must match
  the dispatch exactly through `host.ReviewLaunchMatches`, which review import now shares. Implementation
  launches must match the worker, model and effort of the implementation preflight route the reservation's
  route identity names. A mismatch is `ROUTE_MISMATCH`, a BLOCK. Report completion is not checked here.

## Audit r3 fixes (Liz D4 r3 FAIL, three high findings)

- **R3-F01** `hma host reconcile` now records an observed policy change. When the presented policy differs
  from a stored plan's, the `launch_reconciliation` record carries `revoked_policies` and `observed_at`
  (clock read under both locks). `host.PolicyRevokedAt` treats it like a `policy_revocation` at the
  record's core head. Earlier launches are not dated by it: they were reconciled without it.
- **R3-F02** Policy-change deduplication is per generation (`host.PolicyRevocationNeeded`): a change is
  recorded again unless a recorded revocation already applies to the latest lease generation. The hook and
  reconcile both use it.
- **R3-F03** Review revocations count from the generation's issuer, not from the packet's core head, so a
  dependency rewind before the packet was issued still revokes the review. The unit's own forward moves stay
  legal. Packet issuance itself is not refused; reconciliation makes such a launch a BLOCK.

R3 tests: `TestReviewIssuedAfterDependencyRewind`, `TestReconcilePolicyObservationPersists`,
`TestRepeatedPolicyChangeNewGeneration`. Five mutants were each caught.

## Audit r4 fixes (Liz D4 r4 FAIL, one high, one medium)

- **R4-F01** An imported journal's ledger namespace is a declared namespace (`host.Namespaces`), admitted or
  not, so the transition gate requires a current clean reconciliation whenever any HMA-bound journal exists.
- **R4-F02** Every imported journal must match exactly one admission, including a journal with no attempts

R4 tests: `TestEveryJournalBindsAdmission`, `TestUnadmittedJournalClosesGate`. Two mutants were each caught.
Limit: journals imported before admission existed now block progression until a human disposes the finding.

## Policy at the transition gate (Lennon decision, 2026-10-19)

The r2 open question is closed by human decision. `transition.Input` has `policy_path`. When the run
declares any ledger namespace, the host gate at the two coding progression edges requires it and refuses
with `HOST_POLICY_NOT_CURRENT` unless its digest equals the `policy_digest` of the latest launch
reconciliation. A policy edit after a clean reconciliation therefore closes the gate until the host
reconciles under the new policy. Runs with no ledger namespace are unchanged. Test:
`TestGateRequiresReconciledPolicy` (mutant caught); Liz's probe `TestAuditorD4GateMustDetectPolicyDrift`
now passes.

## Limits (recorded)

- Ledger and HMA times are host clock values (trusted host).
- A policy change is dated when `hma host attempt` first observes it; a change no hook call observed is
  reported as unproven, not dated.
- Legacy review packets without `ledger_namespace` are not scanned.
- An implementation receipt is checked for worker, model and effort only: the verify-loop route binds no
  provider, and the ledger derives the provider from the model.
- Clone baseline is checked at admission and consumption (D3); loop evidence does not record it.
