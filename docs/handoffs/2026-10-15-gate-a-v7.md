## 1. R11 — validity end is a monotone minimum (replaces the "Revocation sets `valid_until`" sentence in v6 §2)

Each reservation, review dispatch, and lease has a fixed **generation identity**: the issuing core approval
record (sequence + head anchor) for a lease; the record's own sequence for a reservation or review dispatch.
A reservation or review dispatch belongs to exactly one lease generation.

For each record:

    valid_until = min(original_expiry, t_r for every applicable revocation event r)

Applicable revocation events: any core rewind affecting the unit or a dependency, terminal outcome, policy or
contract digest change, and lease wall-time end of the record's generation. The value is computed from the
whole chain at import, so ingestion order does not matter. It can only decrease as events are added; nothing
increases it.

A later approval that issues a new lease (v4 §1) creates a **new generation**. It never revives an earlier
generation or any record in it. Records of the old generation keep their `valid_until`; new launches need
new reservations under the new generation.

Interval and ties unchanged from v6 §2: authorized only if `valid_from <= t < valid_until`; equality is
unauthorized.
