## 1. R1 — one issuance rule over legal edges only (replaces v3 §2.2 issuance and walk-through)

Issuance rule (single): a unit's lease derives from the unit's **latest approved core transition whose
target is `IMPLEMENTATION_AUTHORIZATION`**. Per architecture §5.4 the only legal such edges are:

- `ROUTE_SELECTION -> IMPLEMENTATION_AUTHORIZATION` (initial, and after any escalation to Route selection);
- `INDEPENDENT_VALIDATION -> IMPLEMENTATION_AUTHORIZATION` ("correction returns implementation").

Both approvals carry `accepted_plan_digest`; HMA checks the presented `hma.plan/v1` against it. There is no
other issuer. There is no `IMPLEMENTATION_REVIEW -> IMPLEMENTATION_AUTHORIZATION` edge.

Rework paths (all existing legal edges, all human-approved):
- finding at Implementation review or Verification → human escalation to `ROUTE_SELECTION` (same or new
  route, §17) → `IMPLEMENTATION_AUTHORIZATION` → new lease;
- finding at Independent validation → `IMPLEMENTATION_AUTHORIZATION` directly → new lease;
- criterion/plan correction → `PLANNING` (voids all affected leases via plan graph).

Walk-through checks (Gate D tests): 0 launches before the first issuing approval; attempts allowed while
the unit's projected stage is `IMPLEMENTATION_AUTHORIZATION`; refused after the human-approved move to
`IMPLEMENTATION_REVIEW`; refused at Review/Verification until a legal rework edge is approved; allowed
again after `INDEPENDENT_VALIDATION -> IMPLEMENTATION_AUTHORIZATION`. `IsLegalEdge` negatives retained,
including `IMPLEMENTATION_REVIEW -> IMPLEMENTATION_AUTHORIZATION` refused.

## 2. R6 — policy digest source (amends v3 §2.2)

`hma.plan/v1` gains a required `policy_digest` (digest of the effective kernel→org→project→task policy
projection HMA already computes for route coherence). Because the plan is bound by
`accepted_plan_digest`, the policy is human-bound with no new approval field. Active-lease check:
current computed policy digest == plan `policy_digest`; otherwise void and `ESCALATE_TO_HUMAN`.

## 3. R7 — reservation order and admission vs consumption (replaces v3 §3.2 steps 1–2)

Under the host per-run lock:

1. **Replay first.** If a reservation exists for (`controller_run_id`, `attempt_index`,
   `dispatch_run_id`) with the same request digest, return it unchanged — even if the lease has since
   ended or counters are exhausted. Same key with a different request digest → refuse
   (`HOST_RESERVATION_CONFLICT`).
2. **Admission (first call per controller run).** If no `loop_admission` record exists for this
   `controller_run_id`: require an active lease, `escalate_to == "stop"`, envelope route == lease route, and
   envelope `max_attempts`, `max_minutes`, spend cap each ≤ the lease's remaining amounts at this moment.
   Append `loop_admission` binding controller run ID + envelope digest. Admission consumes nothing.
3. **Consumption (each attempt).** Require the admission record with the same envelope digest, an active
   lease, remaining attempts ≥ 1, and the §17 failure-signature rule. Append one `reservation` and count
   it. Envelope-vs-remaining is not rechecked here (it was an admission rule).
4. Unknown launch stays counted; no cancellation path. Counters per unit, monotonic for the run.

## 4. R4 — what the trusted host must do, and what HMA detects (replaces v3 §3.2 "mandatory hook")

Request fields added: live repository root, clone baseline digest (from controller state), ledger
namespace (`AGENT_DISPATCH_STATE_DIR` path digest), envelope digest. Response: `reservation_id`, valid
only for that `dispatch_run_id`, expiring at lease end.

D5 controller contract (Obsidian): an envelope with an `hma` block (`store`, `run_id`, `unit_id`) is
HMA-bound. The controller calls the hook before every launch, including after resume, and does not launch
on non-zero exit or missing response. An HMA-bound envelope without the hook argv is refused at `start`.

HMA detection at import (closure-blocking): every ledger run in the declared namespace whose start time
falls inside the lease window must map 1:1 to a reservation (`dispatch_run_id`); every reservation must map
to at most one ledger run; the envelope digest in the journal must equal the admission record. Any
mismatch → `BLOCK` kernel finding `UNAUTHORIZED_DISPATCH`. Disclosed limit: a host that disables the hook
and hides ledger runs is outside the threat model.

## 5. R8 — review provenance (replaces v3 §4.3 provenance; D6)

D6 receipt fields (`agent-dispatch`, Obsidian): `packet_sha256` (exact prompt file bytes), `head` and
`worktree_sha256` at launch, `output_sha256` of the final message, `report_files` [{path, sha256}] for
declared result paths, `agent`, `provider`, `model`, `effort`, `mode`.

Import rule: HMA generates the review packet itself (target, contract, findings snapshot, bindings) and
records its digest before dispatch. A review imports only if: receipt `packet_sha256` == that digest;
receipt `head`/`worktree_sha256` == the bound target; the imported report's bytes hash to a
`report_files` entry; provider/model satisfy §5 independence against the implementer reservations; the
receipt's ledger run is not one of the unit's implementation reservations. Disclosed limit: receipts are
host-written; under T they are trusted for drift/accident detection only.
