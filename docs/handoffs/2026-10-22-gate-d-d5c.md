## What the packet carries (runs with a bound acceptance contract)

- Header (unchanged): review dispatch id, nonce, dispatch run id, unit, issuing reason, artifact digest,
  implementation record digest, base revision, produced head, diff digest, worktree digest, validity.
- Bound HMA state, inside the packet bytes, so the packet digest covers it:
  - `contract`: the whole approved acceptance contract and its digest (validated against the bound digest).
  - `request` and `request_basis` (`contract.intent`): decision by Lennon on 2026-10-22: the contract's intent is
    the immutable request; no request artifact and no schema change.
  - `unit`: the whole plan unit (every `hma.plan/v1` unit field) from the current lease issuer's plan.
  - `accepted_plan_digest` and `plan_source_record`: both from the current lease issuer (the approval that
    `currentPlanUnit` uses), so the digest and the unit come from the same approval, also after a correction
    approval. `route_approval_digest` stays the route approval's.
  - `policy` and `policy_digest`: the normalised route policy supplied as `policy_path`; its digest must equal
    the contract's policy digest.
  - `evidence`: every evidence record of the unit, plus run-wide records with no unit, with every `EvidenceRef`
    field and a `current` flag that is true only when repository identity, base, head, diff and worktree digests
    all equal the packet target. Current records sort first. Output bodies are not inlined (`output_ref`,
    `output_digest`).
  - `waiver_terms`: replay of the waiver records in chain order, on every record kind, as
    `engine.ProjectResolutionState` decides activity. For each selector that is active at the end, the complete
    stored `WaiverOperation` (or, for a legacy waiver, the stored `Waiver` with `legacy: true`) and its record
    anchor. A packet is refused when an active selector has no term (`HOST_REVIEW_PACKET_WAIVER_INCOMPLETE`).
  - `changed_files` and `line_counts`: the manifest below, and `line_counts: "minimal-lcs"` (see Counting).
  - criteria, findings, active waiver selectors (as before).
- Runs with no bound contract produce unchanged packets: no `contract`, `unit`, `evidence`, `policy`, `request`,
  `plan_source_record`, `waiver_terms`, `changed_files` or `line_counts` keys, `accepted_plan_digest` from the
  route approval as before D5c, no size cap, and the caller's `Task:` text rendered as before.

## One observation of the target

`cmd/hma/observe.go` builds one observation of the target. The packet manifest (`changed_files`) and the D5b
budget facts (`measureChange`) are thin views of it, so they cannot disagree.

- Inventory: paths that differ between the base tree and the HEAD tree (`git ls-tree -z`, literal names), plus,
  for a dirty-approved target, `repostate.ChangedPaths` (the exact set the artifact digest covers: tracked and
  staged changes and untracked non-ignored paths). `git diff` text is never the inventory.
- Per path, the base side is the base tree entry and the target side is the HEAD tree entry (committed) or the
  worktree (dirty): raw bytes, no filters. Status: `added`, `modified`, `deleted`, `type_changed`, `submodule`
  (digest = the commit id). Also `old_mode`, `new_mode`, `binary`, `staged`.
- Paths: read with `-z`, so non-ASCII, quote, tab and newline names work; invalid UTF-8 names are refused
  (`HOST_REVIEW_PACKET_PATH_UNSUPPORTED`); a path under a symlink or non-directory parent is absent, as in the
  snapshot (`lstatInTree` rule, reimplemented without touching `raw.go`); a directory at a path that is a file in
  the tree means "no file entry" (a file replaced by a directory is `deleted` plus the files below it `added`);
  a listed untracked nested repository (`dir/`) is refused, as the snapshot refuses it; a FIFO, socket or device
  is not part of the target and is never opened. A path absent from the base and the target is omitted.
- Bytes: the full target-side SHA-256 is streamed; at most the first 16 MiB of each side is kept for counting.

## Counting

Lines are counted as the minimal edit distance between the base side and the target side (Myers with one
frontier array, a depth cap of 20000 and a work cap of 50,000,000 `(N+M)*D`, lines held as offsets and 64-bit
hashes with byte confirmation, a 1,000,000-line cap). This is the true minimum; git's heuristic `numstat` can
report more (2 of 60 random pairs in the audit; never fewer than HMA's). The packet states it (`line_counts`).
Two flags are explicit and never silent:
- `lines_truncated`: a side exceeded the 16 MiB window. `added` and `deleted` count only the first 16 MiB of
  each side and are NOT a bound on the whole change (an audit showed +65/-161 for a true +0/-160); the packet marks
  the entry and the `max_diff_lines` budget fact is exceeded whatever the counts are.
- `lines_upper_bound`: the work or line cap, or binary content (a NUL byte), was hit. `added` and `deleted` are
  the line counts of the two sides, a sound upper bound; the budget counts their sum.
An empty side or identical bytes never slice or diff.

## Inputs and refusals

- Inputs: `contract_path` (required for a run with a bound contract), `policy_path` (required with it),
  `plan_path` (optional: parsed with `model.ParsePlan`, its digest must equal the lease issuer's).
- Refused before any packet file or dispatch record exists:
  - a contract that is not the bound one, or any contract for a run with none: `ACCEPTANCE_CONTRACT_DIGEST_MISMATCH`;
  - no contract, or no readable policy, for a run that binds one: `HOST_REVIEW_PACKET_INPUT_MISSING`;
  - a policy whose digest is not the contract's: `HOST_POLICY_NOT_CURRENT`;
  - no retained plan and no `plan_path`, or a `plan_path` that is corrupt or has another digest:
    `HOST_REVIEW_PACKET_PLAN_MISSING` (the error names `plan_path`);
  - an active waiver without a term: `HOST_REVIEW_PACKET_WAIVER_INCOMPLETE`;
  - an invalid UTF-8 manifest path: `HOST_REVIEW_PACKET_PATH_UNSUPPORTED`;
  - a contract-bound packet over 2 MiB, or with more than 2000 evidence records or manifest entries:
    `HOST_REVIEW_PACKET_TOO_LARGE` (no silent truncation);
  - the repository changed between the artifact snapshot and the end of the manifest build:
    `HOST_REVIEW_TARGET_CHANGED` (a second snapshot is compared with the binding).
- `plan_path` is validated in memory; the plan is retained only after every refusal check passed, inside the
  dispatch transaction (host then core lock). If the dispatch append fails after the retain, the digest-verified
  plan stays in the store (harmless).

## Limits

- The packet carries no diff bytes and no evidence output bodies: the manifest and the digests bind what the
  reviewer reads in the repository (a review-mode reviewer has repository access).
- During counting, a blob or worktree file is hashed in full by streaming, and only the 16 MiB window is held in memory per side. Earlier anchored capture reads each worktree file in full into memory without this bound.
- The manifest cap (2000 entries) is applied to the path count before the observation reads any per-path bytes,
  so a very large change refuses with `HOST_REVIEW_PACKET_TOO_LARGE` without hashing or counting each file. Reads
  that come earlier are not covered: for a dirty target `repostate.ChangedPaths` (Gate B snapshot logic) reads the
  tracked worktree files, and the packet command takes the artifact snapshot before it builds the manifest. The
  D5b budget measurement has no entry limit and stays exact.
  Observation costs about two git processes per changed path (about 2 ms): a change of ~100k paths approaches the
  10-minute context of the budget measurement and would then fail with a context error.
- Dirty-target worktree reads (Linux): every path component is opened one at a time from the descriptor of the
  directory opened before it (`/proc/self/fd/<fd>/<name>`, `O_DIRECTORY|O_NOFOLLOW` for parents), so a parent
  swapped for a link after it was checked cannot redirect the lookup (audit d5c13l F01). The leaf is examined and
  opened from the retained parent with `O_NOFOLLOW|O_NONBLOCK`; the opened descriptor must be a regular file and
  the same file the `Lstat` saw; reads honor the context. Missing procfs is an error, never "absent". Other
  platforms refuse dirty observation (`dirty target observation requires Linux`; credit and the sandbox are
  Linux-only already); committed targets, read from git objects, work everywhere. This costs macOS and Windows
  the dirty-approved review packet of a contract-bound run.
- Findings import re-checks the live target after it measured the budget facts (`requireLiveTarget`).
- `measureChange` reports truncation as its own fact; the `max_diff_lines` budget is exceeded when the measurement
  is truncated or the line total is over the budget, also when a plan declares the largest integer budget.
- The evidence list keeps history across generations and heads; the `current` flag is what marks the target.
- A refusal of a packet for a target with an untracked nested repository comes from the snapshot (pre-existing).
- Reviews: Claude Opus 5.5 (same vendor family as the orchestrator) PASSED commit `0246dca` with four low findings
  (fixed here) and two advisories (one fixed, one recorded above). `prof / gpt-6-astra` (cross-family) failed
  earlier versions; her run on `0246dca` ended on a provider capacity error (no verdict). No cross-family PASS
  exists yet.
- Policy revocation is not shown in the packet (the packet carries the contract's policy digest and the
  normalised policy); D4 already gates the transition on the current policy.
