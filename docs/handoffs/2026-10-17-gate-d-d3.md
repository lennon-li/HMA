## Command

`hma host attempt --store S --plan P --contract C --policy POL [--request FILE]` is the verify-loop
`authority_hook`. It reads verify-loop's `authority_request` (stdin by default). HMA reads the controller
state at `dirname(ledger_namespace)/state.json`; its envelope must hash (verify-loop canonical JSON) to the
request's `envelope_sha256`, and it must be this controller run, bound to this store, run, and unit, at the
request's live root. The policy file is a route policy; its normalized digest is the current policy digest.

Under the host lock, then the core lock:

1. **Replay first.** Same key (`controller_run_id`, `attempt_index`, `dispatch_run_id`) and same request
   digest returns the reservation unchanged and charges nothing. Same key, other digest, or a dispatch id or
   attempt index reused under another key, or a review packet's dispatch run id:
   `HOST_RESERVATION_CONFLICT`. `launch_eligible` is true only while the reservation's lease generation is
   still active by time, stage, policy, contract, and route (capacity not rechecked), before its
   `valid_until`, and no ledger run `ledger_namespace/runs/<dispatch_run_id>` exists.
2. **Admission** (first call per controller run, consumes nothing): run repository binding and live root;
   route equal to the unit's latest unexpired AVAILABLE implementation preflight (worker, model, effort,
   in both request and envelope; the lease checks that preflight's route grant); active lease;
   `escalate_to == "stop"`; envelope `max_attempts`, `max_minutes`, and `spend_cap_usd` within what remains
   (contract cost unit must be `usd`). Appends `loop_admission` bound to the lease generation.
3. **Consumption:** the admission must match envelope digest, live root, clone baseline, ledger namespace,
   unit, and lease generation (a new generation needs a new controller run); active lease with capacity
   (counters are all of the unit's reservations, across generations); a non-empty failure signature not
   already presented by this controller run; per-attempt cost within the ceiling. Appends one `reservation`
   with `valid_from` (now), `valid_until` (lease end), and the generation, and returns
   `launch_eligible: true`.

A reservation stays charged whether or not the worker launches. Every refusal exits non-zero, so
verify-loop does not launch.

## D3 r1 remediation (Jax)

The clock is read only after both locks are held; if the lease or route preflight ends while the
reservation commits, the charge stays and `launch_eligible` is false. The request namespace must be
`<controller state dir>/dispatch-ledger` (absolute); the clone baseline digest must equal verify-loop's
digest of the state's `repo.workspace_baseline_inventory`. The repeated-failure rule is unit-wide across
controller runs.

## D3 r2 remediation (Jax)

A new reservation (admission or consumption) needs the controller state's latest attempt to be the one the
request names, in phase `dispatching`, with the same index, dispatch id, route, and last failure signature
(verify-loop appends and saves the attempt before calling the hook). It is refused, before any append, when
the ledger already has `runs/<dispatch_run_id>`; a run appearing during commit leaves the charge with
`launch_eligible: false`. Replays of an existing reservation are unchanged.
