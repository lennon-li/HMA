## 1. Launch classes and namespace (R9)

Every ledger run in the declared namespace for the run's lifetime is classified by exactly one HMA record:

- **implementation launch** — matches one `reservation` (§2). Counts against the unit's attempts.
- **review launch** — matches one `review_dispatch` record that HMA appends when it generates the review
  packet (v4 §5): binds `review_dispatch_id`, `dispatch_run_id`, packet digest, target, required reviewer
  independence, issuing reason (per-change review / checkpoint audit / final audit). It does not count as an
  implementation attempt. A review dispatch requires the unit's current stage to admit review (any stage at
  or after the implementation work it reviews) and a reviewer route that satisfies independence against all
  implementation reservations for the unit.

A ledger run with no matching record, or matching two, is `UNAUTHORIZED_DISPATCH` (BLOCK). Role label
alone is never accepted: a `review_dispatch` whose receipt shows write mode (`mode != review`) or whose
`dispatch_run_id` also appears in a reservation is unauthorized.

## 2. Launch-time validity (R4, R7 residual)

Reservations and review dispatches carry `valid_from` (record time) and `valid_until` (lease end, or for
reviews a fixed short TTL). Hook replay (v4 §3 step 1) still returns the historical record unchanged and
stays counted, but adds `launch_eligible: false` when the lease is no longer active; the D5 controller must
refuse launch unless `launch_eligible: true`.

Import reconciliation scans **all** ledger runs in the namespace from the run's first core record to import
time — not only the lease window. For each, with `t` = ledger `started_at`:

1. no matching record → `UNAUTHORIZED_DISPATCH`;
2. matching record but `t < valid_from` or `t > valid_until` → `UNAUTHORIZED_DISPATCH` (covers launch before
   issuance, after expiry, after revocation by rewind/terminal: revocation sets `valid_until` to the revoking
   core record's time);
3. matching record and `t` within validity → authorized.

A reservation with no ledger run stays counted and grants nothing later. Disclosed limit (T): ledger times are
host clock values.

## 3. Review import eligibility (R8)

A review imports only when all hold, in addition to v4 §5:

- receipt `dispatch_run_id` == the `review_dispatch` record's ID, in the declared namespace;
- receipt `mode == review`; receipt terminal state `completed` with exit code 0;
- each imported report file's `sha256` is in the receipt's `report_files` **and** the file's mtime and the
  receipt's `report_files` entry are after the receipt's `started_at` (stale pre-existing report refused;
  D6 records report hashes only for files modified during the run);
- verdict map is total: `pass` → APPROVE; `fix-required` → REQUEST_CHANGES; `conditional-pass`,
  `blocked`, `unknown`, `not-evaluated`, missing, or any other value → no approval, `ESCALATE_TO_HUMAN`.

A failed, running, missing, wrong-mode, wrong-run, or stale-report review cannot resolve a finding or credit a
criterion.
