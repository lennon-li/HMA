# Gate D D5a — criterion credit (implementer handoff)

Scope: Gate A v3 §4.3 criterion credit and Gate C scope §0.1 row "Positive criterion credit"
(`TestScorecardOnlyIndependentCredit`, `TestPartialNeverVerified`). D5b (findings disposition) and D5c (full
review packet) are later parts.

## Behavior

- `hma host credit` (input: envelope, `review_record`, `report_path`, `contract_path`,
  optional `dirty_worktree_approved`) holds the host run lock, then the core run lock.
- It refuses unless:
  - the run is open and the presented contract's digest is the run's bound contract digest;
  - the review is the unit's latest imported review for its current implementation, answers the latest
    review dispatch, has verdict APPROVE, isolation `isolated`, and report verdict `pass`;
  - the report bytes hash to the review's recorded report digest;
  - the unit holds an approved route, and the packet's root and base are the approved repository;
  - the live snapshot is the reviewed artifact (head, diff, worktree).
- For each criterion the unit's current lease-generation plan advances (`criteria_advanced`), HMA runs the
  contract check itself (no shell; same argv safety rules as loop evidence; working dir inside the root),
  checks the worktree did not change, retains the output, and appends a core evidence record.
- Disposition per criterion: PASSED only when HMA's check exited 0 and the report lists the criterion id with
  status `pass`; FAILED when the check exited non-zero; PENDING otherwise (missing from the report).
- It appends one core criterion record (other criteria carried unchanged) and one `criterion_credit` host
  record binding the review, report digest, artifact, contract, per-criterion evidence record, exit code,
  report status, and disposition.
- `hma transition` to VERIFIED_SUCCESS or VERIFIED_WITH_WAIVERS refuses with `HOST_CREDIT_REFUSED` unless every
  PASSED criterion: (a) is in a core criterion record that a `criterion_credit` record appended and that is the
  latest criterion record; (b) has PASSED as its latest credit result; (c) relies on a review that is still the
  unit's latest for its current implementation. A self-written criterion record (a scorecard) credits nothing,
  and carrying it forward through a credit does not launder it.

## Audit r1 fixes (Liz D5a FAIL: F01-F03 high, F04 low)

- **F01** A review credits only if the contract digest and the unit's lease issuer anchor at the review
  dispatch's core head are still the current ones (`reviewBinding`). A contract change or re-authorization
  needs a fresh review.
- **F02** The verified-outcome guard (`requireIndependentCredit`) now also requires, per PASSED criterion,
  that the credit's contract digest and issuer anchor are current and that its artifact digest equals the
  closure artifact HMA observes now in the transition's repository (the transition input's
  `repository_root`, `base_revision`, and `dirty_worktree_approved` are used).
  `CriterionCredit` gained `issuer_head_anchor`.
- **F03** `checkDir` and `evidence.Capture` resolve symlinks in the root and the working directory before
  the containment check, and the check runs in the resolved directory.
- **F04** The credit response carries `next_action`: `REMEDIATE_OR_ESCALATE` after a failed check,
  `ESCALATE_TO_HUMAN` when a criterion stays pending, else `CONTINUE_HMA_TRANSITION`.

R1 tests: `TestCreditRefusedAfterReauthorization`, `TestCreditGuardTargetDrift`, `TestCreditSymlinkWorkingDir`,
`TestCaptureResolvesWorkingDirSymlinks`, `TestCreditNextAction`. Mutants caught: artifact, issuer in the guard,
symlink resolution (credit and capture), next action, removal of `reviewBinding`. Not separable by any
reachable state: the contract half and the issuer half of the review binding (a contract change forces a new
route approval, so a new issuer); both stay as defense in depth. `req.WorkingDir = wd` in `Capture` only pins the
resolved path against a swap after the check (outside the trusted-host model).

## Audit r2 fix (Liz D5a r2 FAIL: F05 high; F01-F04 FIXED)

- **F05** `unsafeLoopArgv` (shared by credit and loop evidence) looked only at the token after `git`, so
  `git -C <dir> config ...` passed. `gitSubcommand` now skips only `-C <dir>`, `--no-pager`, `-P`,
  `--no-optional-locks` and `--literal-pathspecs` (and its no- form), then judges the real subcommand. Any
  other option (`-c`, `--git-dir`, `--work-tree`, `--config-env`, equals forms, unknown) or a missing
  subcommand fails closed. Test: `TestUnsafeLoopArgvGitOptions`; Liz's `TestIndependentGitOptionSafety` passes.
  The mutant that restores next-token parsing is caught.
- Limit: this is a deny list of known-mutating commands plus a git option allow list. A check that is
  itself a script or a tool with its own side effects is outside it (scope §4b).

## Audit r3 fix (Liz D5a r3 FAIL: F06 high; F01-F04 FIXED, F05 PARTIAL)

- **F06** A configured git alias (`!` shell alias or an alias to `git config`) and unlisted mutators such as
  `git init` still passed the deny list. Git checks now use an allow list: `gitReadOnly` names built-in
  read-only subcommands (status, diff, log, show, rev-parse, rev-list, ls-files, ls-tree, cat-file, describe,
  blame, grep, show-ref, merge-base, name-rev, shortlog, check-ignore, diff-tree, diff-index, version).
  Built-ins cannot be overridden by an alias, so an alias name, an unknown subcommand, or any mutator is
  refused. `gitWritesArg` also refuses `--output`, `--ext-diff`, `--textconv`, `--open-files-in-pager`/`-O`,
  `--exec`, `--upload-pack`. The old publish deny list is removed. Shared by credit and loop evidence.
  Tests: `TestUnsafeLoopArgvGitOptions` (extended); Liz's `TestR3*` reproductions pass. Four mutants caught.
- Limit: the check's environment is HMA's, but `git` reads the repository's and the user's configuration;
  a read-only built-in with a configured external helper (diff driver, textconv) is only refused when
  requested by a flag. Other tools remain outside this deny/allow logic (scope §4b).

## Audit r4 fixes (Liz D5a r4 FAIL: F07, F08 high)

- **F07** Git accepts any unambiguous prefix of a long option, so `grep --open-files=` ran a pager command.
  `gitArgsUnsafe` refuses any long option that is a prefix of `--output`, `--ext-diff`, `--textconv`,
  `--open-files-in-pager`, `--exec`, `--upload-pack` or `--filters`, and any short bundle containing `O`.
- **F08** `diff`, `log` and `show` run a configured external diff or textconv driver. A check using them must
  pass both `--no-ext-diff` and `--no-textconv`; the recorded argv then shows it. `blame` is removed from the
  allow list (no flag stops its textconv). `repostate.GitEnv` (used by every captured command) drops the
  caller's `GIT_CONFIG*` variables and sets no user or system config, `core.fsmonitor=false` and
  `core.hooksPath=/dev/null`.
- Tests: `TestUnsafeLoopArgvGitOptions` (extended), `TestGitEnvDisablesConfiguredLaunchers`; Liz's `TestR4*` pass.
  Mutants caught: prefix match, short `O`, both patch flags, one patch flag, `blame` listed, env hardening.
- Limit (unchanged): repository-local configuration other than the two keys above (for example a `cat-file
  --textconv` or `pager` entry) is not neutralized; the allow list and flag rules are the barrier.

## Design change after r4 (approved forms)

Four audit rounds each found another way around the git deny/allow rules (F05-F08). On 2026-10-19 the
implementer replaced them with approved forms, with Lennon's go-ahead. `gitFormAllowed` (shared by credit
and loop evidence) accepts a git check only when: global options are only `-C <dir>`, `--no-pager`, `-P`,
`--no-optional-locks`; the subcommand is in `gitForms` (status, diff, log, show, rev-parse, ls-files,
show-ref, merge-base, cat-file, version); every option before `--` is an exact spelling on that form's list
(so no prefix can stand for another option); `diff`, `log` and `show` carry `--no-ext-diff` and
`--no-textconv`; no empty argument. Everything else, including aliases, grep, blame and every mutator, is
refused. `repostate.GitEnv` still drops caller git configuration. Test: `TestUnsafeLoopArgvGitOptions`
(rewritten, 32 cases); five mutants caught (the empty-argument check is redundant with `unsafeLoopArgv`'s own empty-argument refusal and stays as defense in depth). Cost: some legitimate git checks are refused until their form is added.

## Audit r5-r6 fixes (Liz D5a r5 F09; Prof D5a r6 F10-F12)

Findings: F09 repository-local git config can start a helper (signature program); F10 `git -C` selects a

- `git -C` is refused in checks (`gitSubcommand`): a check runs in the approved root only.
- `repostate.GitEnv` also sets `log.showSignature=false`.
- Tests: `TestCaptureGitRepositoryConfig` (filter, comment-backslash, signature, include attacks; nested

  `TestCreditRefusedUnderHelperConfiguration`, `TestUnsafeLoopArgvGitOptions` (-C cases),

  Mutants caught: wiring, allow list, nested check, worktree check, -C, subsection form. Redundant, not

- Limit: only keys on the allow list are tolerated; a repository with other local settings (aliases, hooks

## Audit r9 fixes (Prof D5a r9 FAIL: D5AR9-F01, F02 high)

- **F01** The fingerprint skipped the root directory and directories with no listed file, so a file created
  and removed during a check went unseen. `Fingerprint` (now `hma-fingerprint-v2`) walks every directory in
  the worktree, root and empty ones included, except `.git` and directories git ignores, and records mode,

- **F02** Validation parsed `.git/config` in one git process and the command reopened it in another, so a
  writer could add a helper in between. `PrepareGitExecution` (replaces `CheckGitRepository`) reads the
  config once, writes it to a private mode-0400 git directory, validates that copy with git's own parser,
  and `Capture` runs git with `GIT_DIR=<private>` and `GIT_WORK_TREE=<root>`. The private directory
  copies `HEAD` (git rejects a symlinked one) and links refs, objects, index, packed-refs, shallow and
  info from the real repository; git replaces the index link with its own file if it refreshes, so the real
  index is not written. The bytes checked are the bytes git reads. `rev-parse --git-dir` is now an approved
  form. Tests: `TestCaptureGitUsesValidatedConfig`, `TestCaptureGitSeesRealIndex`; Prof's
  `TestAuditorGitConfigurationRace` and the other 8 `TestAuditor*` tests pass. Mutants caught: GIT_DIR
  wiring, private bytes, index link. Not separable by any state: validating the private copy instead of the

- Limit: the real objects, refs, `info/attributes` and `info/exclude` are still read live (a writer who edits
